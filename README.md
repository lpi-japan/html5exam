# html5exam

HTML5試験の出題範囲を管理するためのリポジトリ。なお現在進行中の新ver.開発において認定名や試験ラインナップから刷新する可能性がある。

本READMEでは、ファイルの使い分けや変更・記述のルールなど「出題範囲検討というワークの進め方」の基本ルールを書く。

## このリポジトリのファイル構成

| ファイル | 役割 |
|---------|------|
| `改訂概要.md` | 改訂プロジェクトの背景・方針・キーワード割当て・レベル境界の考え方 |
| `objectives_markup.md` | **新版** マークアップ Level 1 の出題範囲（作成中） |
| `objectives_programming.md` | **新版** プログラミング Level 1 の出題範囲（作成中） |
| `objectives_level2_new.md` | **新版** Level 2 の出題範囲（マークアップ・プログラミング統合、再編中） |
| `en_objectives_markup.md` / `en_objectives_programming.md` | 英語版（新版への追随は未着手） |
| `objectives_level1.md` / `objectives_level2.md` | **現行版** ver.2.5 の出題範囲（参照用） |
| `decision_records.md` | 出題範囲の設計判断の履歴と根拠（出題の中身に関する、客観的に判断可能な問いに限る） |
| `期待される行動例.md` | 出題範囲外だが認定取得者に期待される業務行動の例 |
| `refs/` `resources/` | 参考資料・旧版メモ |

## 作業ルール

### 変更の種類とコミット分割

出題範囲への変更は以下の3種類に分類し、**種類をまたいで同一コミットにまとめない**。

| 種類 | 内容 | 備考 |
|------|------|------|
| **リファクタ** | 出題内容を増減させずに、記載をよりMECEで整理されたツリー構造に書き換える | 内容の実質的な変更なし |
| **試験間移動** | 出題項目を試験をまたいで移動させる（例：マークアップ→プログラミング） | 全体の出題量は変わらない |
| **内容増減** | 出題項目を追加・削除する | 必ず客観的な根拠が必要（後述） |

### 内容増減の判断基準

出題項目を増減させる場合は、必ず客観的な理由を明示し、`decision_records.md` の判断記録と連動させる。どういう判断に基づいて増減させたかをいつでも説明できる状態を維持すること。レベル1・レベル2どちらに置くかの判断基準は `改訂概要.md` の「レベル1とレベル2の境界の考え方」に従う。

理由なく「なんとなく追加・削除」しない。増減を伴う変更は仮置きでもその判断根拠が分かるようにする (≒レビュー可能な形にする)。

### 出題範囲文の書式

出題範囲文は以下の階層構造で記述する。

```
試験 (Exam)       … Markdown 見出しレベル 1
  主題 (Section)  … Markdown 見出しレベル 2
    副題 (Topic)  … Markdown 見出しレベル 3、末尾に (重要度: N) を付記
      概要        … 単文または数個の箇条書き。その副題で問いたい視点を表す
      詳細        … 2階層の箇条書き
```

**表記ルール**

- アルファベット単語の前後には半角スペースを入れる（例: `HTML 要素`）
- カッコは半角 `()` を使い、前後に半角スペースを入れる
- コマンド・関数・プロパティ名などはバッククォートで囲む（例: `` `display` ``）
- 技術仕様への参照は footnote 形式（`[^label]` を本文に、`[^label]: 仕様名 — URL` をファイル末尾に）で記載する。仕様名・レベルは必ず MDN や W3C の公式ページで確認してから記入する。記憶や推測で書かない。確認できない場合は `（要出典）` と記す。
